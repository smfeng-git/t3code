# AI 接入入口（维护者使用）

使用者先读 [README.md](README.md) 与 [SETUP.md](SETUP.md)，不要把开发流程重复交给使用者。新版 `Start.cmd` 仍为另行交付的本地预览工具，不在本次文档提交或安装包中；未取得工具时不能执行下列新版启动器步骤。

1. 阅读仓库 AGENTS.md，确认用户选择 Codex、Pi 或两者。只读检查版本、真实路径、Windows/WSL 环境和既有改动，不打印凭证。
2. 核实提供的是匹配的定制安装产物。没有产物时按 [DEVELOPMENT.md](DEVELOPMENT.md) 完成构建交付，不能把克隆源码等同安装完成。
3. Codex 统一走 `Start.cmd`：自动准备连接桥与适配器，首次选择路径、手动在 T3 设置一次。用户确认后可以正常退出或强制退出已识别的 Codex 进程，不按名称批量杀进程。不要改写真实 T3 数据库。
4. Pi 先按开发说明检查补丁与实际版本。`git apply --check` 失败时适配，不强制覆盖；已应用时可用反向检查辨别。窄测试为 Pi Web 的 `node --test lib/rpc-manager-shared-reads.test.mjs`，另需该工作区类型检查。为用户提供其真实环境的启动方式和地址；不得声称 Windows 启动脚本会启动 Pi Web。
5. 检查登录配置是否在构建时注入；事后设置环境变量不能修复旧前端包。Windows 前端与 WSL 后端分别核对，不复制他人的 runtime hash 路径。
6. 按 [ACCEPTANCE.md](ACCEPTANCE.md) 验证：已有会话可读、两端同会话续聊、新会话自动发现、浏览器读页分开记录。新会话自动出现在 Codex 侧栏仍有缺口，不能以手动打开代替。
7. 交付版本、启动入口、实际验证结果及未验证项。不包含私人配置、授权链接或聊天数据。日志先去除敏感信息。

真实消息测试先征得用户同意，使用无关紧要的会话和短消息，不修改真实项目。当前历史验收记录见 RELEASE-NOTES.md，不等于当前启动器已完成 Windows 实机验证。
