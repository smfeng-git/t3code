# 接入与日常使用

先从 [首页的下载入口](README.md#当前可下载的测试构建) 获取程序。安装包和共享启动工具分开交付，不要把下载源码、安装 T3 和启动共享后端当成同一步。

## 下载、安装与验证

### 1. 下载同一次构建的程序

打开 [构建 #42339988640](https://github.com/smfeng-git/t3code/actions/runs/42339988640)，登录 GitHub，在 **Artifacts** 下载 `custom-windows` 和需要的 `custom-android`，分别解压 ZIP。

- Windows：运行 `T3-Code-0.1.7-preview.20261107.2-x64.exe`，用于 Windows x64。
- Android：将 `T3-Code-Preview-Android-arm64.apk` 传到 ARM64 手机安装。
- WSL：Windows 包已携带匹配后端，通常不需要手动解压 `custom-wsl-runtime`，也不要覆盖其他正在使用的 WSL 环境。

对应源码提交为 `73ddbe69d90ae9f3ff2230d1aaaa5bb4cb0e8466`。保存构建链接以便反馈问题；不要混用其他运行记录下的同名文件。下载需要 GitHub 登录及仓库访问权限，Actions 产物过期后需向提供方索取匹配版本。发布草稿不是公开下载入口。

下载前可查看 [本次改动与验证结果](README.md#本次改动与验证结果)。尺寸面板层级、横屏滚动、逐级返回三项已由用户实机验证通过。旧构建 `42273370104` 不含这些修改，但版本号和文件名相同，不能仅凭 `.20261107.2` 判断新旧；安装前可按 [ZIP 校验值](README.md#下载文件校验) 核对。

### 2. 安装或升级

**Windows**：先结束任务并正常退出旧 T3，保留已有配置与数据，再运行安装包。本次 Windows 包未做 Authenticode 签名；若系统提示未知发布者，先确认来源，不要为了安装而关闭系统安全防护。

**Android**：本次沿用原项目 preview 标识：应用名 `T3 Code Preview`、包名 `com.t3tools.t3code.preview`、登录回调 `t3code-preview`。安装时若需要允许来源，仅授权实际用于打开 APK 的应用。

- 已有同包名且签名兼容的版本时，可尝试覆盖安装；版本号等条件也可能影响升级。
- 若提示签名冲突、版本过低或无法安装，**不要先卸载旧版或清除数据**。保留完整提示，交给提供方确认。
- 官方 production、development 或旧自定义包名可能是另一份应用，并非覆盖升级；不要假定它会继承旧应用的登录和配对状态。

本次使用既有定制签名，不是官方签名。保留原包名和登录配置，不等于已证明官方登录服务接受所有定制客户端。

### 3. 先检查基础功能，再检查定制功能

1. 打开 Windows 和手机应用，确认能正常进入界面，检查原有登录是否保留。
2. 若需要登录，使用自己的账号，检查登录后能否正常返回应用。不要为了测试而先注销仍有效的账号。
3. 检查 T3 Connect，并让手机连接自己的环境。只有完成实际连接，才能认为这一项通过。
4. 已配置共享后端的用户沿用现有启动方式，选择正确环境和同一测试会话，分别从两端发一条短消息，等待完成后检查是否可见且无重复。真实消息会使用模型额度。
5. 手机浏览器横屏、缩放和批注使用本次配套的 APK 与宿主验证。不要拿原版手机客户端验证新增控件。

当前 CI 构建与产物检查已通过；用户另外确认了本次手机尺寸面板层级、横屏滚动及逐级返回三项实机验证通过。**这不代表登录、T3 Connect、共享聊天或所有设备均已验收。**反馈时附构建编号、设备系统、失败步骤和错误提示；不要发送密码、token、授权链接或私人聊天内容。

### 4. 全新环境的共享接入边界

上述 Artifacts 不包含新版 `Start.cmd`。只安装 T3 不会启动 Codex 共享后端，也不会部署 Pi Web。

- 已接入用户：继续使用原有启动入口，不用为了安装新版 T3 重新初始化整套配置。
- 新用户：可以先完成安装与登录验证；Codex 共享接入还需提供方交付并验证完整配套工具，Pi 还需兼容的 Pi Web 与其启动方式。
- 下方 Codex 步骤仅适用于已另外取得新版工具的测试用户，不代表当前安装包自带这些文件。

## Codex 首次接入（另需新版工具）

**状态：新版工具尚未作为本次构建附件发布，且未完成配套实机验收。** 以下步骤不能仅凭下载 Windows 安装包执行。

### 1. 放好工具，双击启动

将接入目录放到自己可写的固定位置，例如 `C:\Tools\T3Shared`，路径不要含 `%`、`!`。不要放在系统保护目录，不需要管理员权限。

双击根目录的 **`Start.cmd`**。找到唯一可用位置时自动使用；找不到或有多个候选时才需要选择：

- Codex 应用的位置：安装的桌面应用，不是命令行程序。
- Node.js 的位置：通常会从 PATH 自动找到。
- Codex 命令行程序：优先使用 Codex 应用目录里的 `resources\codex.exe`。
- Codex 数据目录：通常是 `C:\Users\你的用户名\.codex`，使用原来已登录的目录。
- 定制 T3 桌面程序的位置：不要选择安装器或卸载程序。

有多个候选项时输入编号。找不到时粘贴完整路径。工具记住这些选择，自动生成连接文件和编译启动适配器，不要求你执行命令。

Codex 已运行且需要重新启动时，工具会征求确认并尝试关闭；仍未退出时提供强制关闭后继续启动的选项。请先完成任务，强制关闭会中断执行，可能丢失尚未保存的内容。

### 2. 在 T3 中连接一次

启动成功后，进入 **Settings → Providers → Codex**，选择本机 Windows 环境中使用现有 Codex 的实例：

| 设置                       | 填写内容                                   |
| -------------------------- | ------------------------------------------ |
| Binary path                | 启动窗口显示的 `codex-shared.cmd` 完整路径 |
| Home path                  | 启动窗口显示的 Codex 数据目录              |
| Follow Codex conversations | 开启，用于自动发现和跟随已有聊天           |
| Shadow home                | 留空                                       |

记下原来的设置，方便以后恢复。启动器不直接修改 T3 设置或数据库。填好后在启动窗口确认，下次不再显示填写步骤；更换相关路径后会再次提醒。这个确认只记录你已完成设置，不代表脚本已检测到 T3 的实际配置。若找不到这些选项，先确认安装的是提供方交付的定制版本，而不是官方旧版。

不要搬动接入目录；搬动后需要重新启动并更新 Binary path。

### 3. 确认接入成功

1. 在 Codex 新建一个无关紧要的测试会话，发送一句简短文字并等待结束。
2. 在 T3 找到同一个会话；首次导入可能在 Settled，注意选择正确环境。后续已保存消息通常约五秒同步，首次历史扫描可能更久。
3. 从 T3 在同一会话回复一句文字，确认 Codex 也能看到，且没有重复发送。

验证会使用你的模型额度。不需要通过真实项目改动验证。

## Codex 日常使用

以下适用于已配置并验证新版启动工具的环境；只有本次安装包的用户继续沿用既有启动方式。

- **启动**：双击 `Start.cmd`。已有可验证的正确实例会复用，不重复启动共享后端。
- **退出启动窗口**：成功后按回车即可，不影响两个应用。
- **退出应用**：先结束任务，再正常退出 T3 和 Codex；退出 Codex 会停止它持有的共享服务。
- **软件更新**：启动器自动检查并准备，无需判断文件版本或路径变化。若启动失败，可重试或打开日志目录。基础检查不代表所有功能兼容，更新后仍建议先用测试会话验证。
- **不再使用共享功能**：结束任务，退出 Codex，在 T3 恢复原来的 Binary path/Home path，用原快捷方式启动。不会删除历史聊天。

**已知限制：**T3 新会话不保证自动出现在 Codex 侧栏；任意 Codex 版本组合也不保证兼容。先以已有会话双向续聊为判断依据，不能把手动打开会话当作自动发现已修复。

## Pi Web 接入

请先由提供方准备兼容的 Pi Web 和定制 T3 后端，并给出 Pi Web 地址、Pi 路径及启动方式。**本目录的 `Start.cmd` 只启动 Windows Codex 和 T3，不会部署或启动 Pi Web/WSL。** 未拿到这些交付内容时，不要自行尝试补丁或猜路径。

1. 用提供方交付的方式启动 Pi Web 和相应 T3 后端。
2. 在 T3 切换到该后端所在的环境，进入 **Settings → Providers → Pi**，启用 Pi。
3. Binary path 填提供方给出的 Pi 路径；Pi Web shared backend 填该后端可访问的地址。同一 WSL 内可类似 `http://127.0.0.1:30141`，不能照抄其他电脑的地址。
4. 如 Pi Web 设置了密码，在 provider 环境变量中添加 `PI_WEB_PASSWORD` 并标为敏感。
5. 共享会话使用 Full access，工具权限由 Pi Web 管理。

用测试会话分别从 Pi Web 和 T3 发一条消息，等待完成后在另一端确认。Pi Web 必须保持运行；不要让独立 Pi 进程同时写入同一会话。

首次历史可能归入 Settled；后续已完成消息约五秒同步，不保证外部输出逐字直播，也不双向镜像破坏性回滚或删除。停止共享时清空共享地址，已有 T3 显示记录会保留。

如果 Pi 运行在 WSL，Windows 安装成功不代表 WSL 后端也已更新，应由提供方交付并验证对应后端。

## 手机连接

先完成电脑端验证，再在手机 T3 中添加你自己的环境，使用该环境提供的配对入口。Windows Codex 与 WSL Pi 是两个环境时分别配对。不要使用别人提供的私人授权链接、token 或登录文件。

普通共享会话依赖后端能力；如需本分支新增的手机横屏、元素批注功能，还需要匹配的定制 APK 与更新后的宿主。官方手机 App 不会自动获得这些新控件。

## 遇到问题

- 找不到 `Start.cmd`：本次 GitHub 安装包不包含它，不是解压失败；先按上面的共享接入边界处理。
- 安装、登录或回调失败：记录构建编号及系统提示，反馈给提供方；不要通过卸载、清空数据或修改认证地址来盲目重试。

以下恢复选项仅存在于另行交付的新版启动工具中：

- 启动未完成：窗口提供重试或打开日志目录。把 `codex/startup.log` 交给接入包提供方；日志可能含本机路径，分享前检查。不需要自行查 PID 或执行清理命令。
- 应用一直不退出：使用窗口中的强制关闭选项，但先确认没有需要保留的任务。
- 连接地址被其他服务占用：工具不会擅自关闭无关程序或更改已保存的地址。此类情况目前需要提供方处理，重试不保证解决。
- T3 看不到历史：确认使用正确环境、开启 Follow Codex conversations，并查看 Settled。
- 更换安装位置：再次启动，按提示重新选择找不到的软件路径。更新后仍无法使用时，把更新的软件版本及日志交给提供方；不要反复重新安装或清空聊天数据。

当前脚本已配套隔离测试；Windows 实际应用首启、强制重启和真实聊天需要提供方按交付清单验证，不能仅凭测试通过就声称所有机器可用。
