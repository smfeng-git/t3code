## 启动器

- 在不含 config、指纹和编译产物的新目录，双击 Start.cmd；按提示选择路径，自动初始化并打开 Codex/T3。
- 缺少 Python、Node 或编译器时有明确提示，不假装启动成功。
- 路径含空格可用；接入目录位于普通用户可写位置。
- 旧 config 保留，补充 T3 路径，不覆盖未知字段。
- 重复双击不产生第二个共享后端；旧 runtime 文件不能冒充有效服务。
- 正常 Codex 已运行时先询问，取消后不关闭；确认后正常退出并重开。
- 正常退出超时后再次询问；确认强制关闭后重新启动，取消则不强制结束。
- 同名其他路径的进程和无关端口占用者不受影响；PID 复用时重新核对身份。
- 软件更新自动执行基础检查，不让用户批准指纹或判断协议兼容；检查失败不更新指纹记录。启动失败不自动重放请求，也不打开一个貌似已连接的 T3。
- 首次 T3 填写步骤在用户确认完成后不再重复；相关路径改变后重新提醒，不把用户确认当作自动检查 T3 设置。
- 关闭启动窗口不影响服务；结束 App 后不遗留其拥有的后端。

隔离测试：在 codex 目录运行 `python -B test-start.py -v`。此测试不能证明 Windows 真实进程行为。另用 `python test-app-owned.py` 检查原生适配器和真实 CLI 的隔离协议行为。

## 实际会话

1. Pi Web → T3 和 T3 → Pi Web 各发一条短消息，各执行一次；检查新目录、fork、改名、首次 Settled、后续活跃和重启去重。
2. Codex 两端在同一测试会话双向续聊，再验证工具、审批、停止和重连。
3. 单独记录 T3 新建会话在 Codex 侧栏的自动发现情况：仍有已知缺口，不得以手动打开算通过。
4. App 浏览器实际读页；冷启动使用 60 秒工具超时。认证失败不能通过复制其他会话授权解决。
5. 手机连接自己的正确环境，看到相同最终消息；定制批注需配套 APK 与宿主。
6. 退出和回退后普通模式可用，历史保留。
